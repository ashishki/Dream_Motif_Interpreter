# Phase 23 — Test 9 Full Text, English Entries, Numeric Feedback

Last updated: 2026-05-17
Status: Implemented — Test 9 regressions closed; deterministic full-text routing added

## 1. User Feedback

Test 9 (2026-05-15) reported three issues:

1. When asked for the full text of a specific dream, the bot sent only part of the text and said the archive text was cut off, while Google Docs contained the full dream.
2. Several English-language dreams were added to Google Docs; confirm the system can ingest and search English text.
3. Temporarily remove the 1–5 rating prompt because digit-only replies conflict with numbered choices in normal conversation.

## 2. Findings

- `_format_dream_detail_payload()` truncated `detail.raw_text` to the first 2000 characters before the LLM saw it.
- Follow-up finding (2026-05-17): after the tool truncation was removed, full-text answers could
  still be shortened because the final answer was regenerated by the LLM with `max_tokens=1024`.
  Telegram splitting happens after generation, so it could only split the already-shortened answer.
- Second follow-up finding (2026-05-17): when the user repeated the same full-text request, the LLM
  could answer from stale conversation history without calling a tool at all. In the observed case
  the user asked `Приведи полный текст сна dreamwork, three women`, and no `get_dream` call happened.
- Telegram responses were sent as a single message, so long full-text answers also needed safe message splitting under Telegram's length limit.
- Google Docs segmentation already accepted English body text, but needed explicit coverage for common manual English headings such as `15.05.26 - Title`, `05/16/26 - Title`, and `May 16, 2026 - Title`.
- Exact and hybrid retrieval used PostgreSQL `russian` FTS only. English can still be found semantically, but exact English word recall is safer with `simple` FTS alongside Russian FTS.
- Numeric feedback capture was unconditional in the Telegram handler once pending feedback existed.

### WS-23.4 — Deterministic Full-Text Reply Bypass

Scope:
- `app/assistant/chat.py`
- `tests/unit/test_assistant_chat.py`

Acceptance criteria:
- Explicit full-text requests such as "полный текст сна", "целиком", and "full text" still let the
  assistant resolve the target dream through tools.
- Once `get_dream` or a single `search_dreams_by_title` match returns a full dream, the bot sends
  the archive text directly instead of asking the LLM to reprint it.
- If the user includes a target title/query in the same full-text request, the bot resolves it before
  the LLM call, so stale chat history cannot answer instead of the archive.
- Direct replies preserve the tail of long dream text and include date/title context.
- Regression tests prove no second LLM call is made for direct full-text delivery.
- Regression tests prove the real repeated-request pattern ignores stale history and does not call
  Anthropic at all.

If the LLM still calls get_dream/search_dreams_by_title for a query without an inline target, format the Date/Title/Text payload directly before final generation. Keep normal analysis/search flows unchanged. Add tests that a long dream result is returned with its final line, that client.messages.create is called only once for tool-use fallback, and that a repeated full-text title request with stale history does not call Anthropic.

## 5. Light Review Notes

- Full-text fix is low risk: it removes a presentation-layer truncation and does not change stored dream data.
- Long-message splitting is scoped to assistant replies and keeps short replies as a single Telegram message.
- English support is additive: Russian FTS remains active; `simple` FTS adds exact English keyword recall.
- Numeric feedback storage remains available, but user-facing capture is off by default.

## 6. Residual Risks

- Direct full-text bypass depends on the target dream resolving to `get_dream` or one unambiguous
  title match. Ambiguous title matches still require the user to choose a specific dream first.
- Live English Google Doc smoke was not run in this local verification slice.
- Emoji reaction semantics remain dependent on explicit `TELEGRAM_REACTION_FEEDBACK_MAPPING`.
